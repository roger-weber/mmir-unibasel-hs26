Fine-Tuning

Where this is used

Query Understanding recognizes named entities with a transformer fine-tuned for token classification, and Result Generation extracts answer spans with a model fine-tuned on SQuAD. Semantic Similarity with Transformers trains bi-encoders and cross-encoders, both fine-tuned transformers. contrasts a frozen backbone with a linear probe and full fine-tuning for image networks, and Evaluating RAG discusses when fine-tuning is the right tool and when retrieval is.

Pretraining gives a transformer a general model of language, but it does not teach it a task. Fine-tuning adapts a pretrained model to a task with labeled examples: it adds a small task-specific layer, the head, and continues training. Because the pretrained layers already encode most of what the task needs, a few thousand labeled examples are often enough where training from scratch would need millions. This section describes the heads for the most common tasks, the choice between freezing and training the pretrained layers, the hyperparameters that matter, parameter-efficient methods such as LoRA, and a complete fine-tuning loop.

Task Heads¶

An encoder computes one contextualized vector ht\mathbf{h}_tht​ per input token. A head turns these vectors into the output the task needs.

Sequence classification assigns a label to a whole text, for example a sentiment or an intent. The head takes a single vector for the sequence, the output at the [CLS] token or the mean over all token vectors, and maps it with one linear layer to KKK logits, followed by the softmax of Softmax:

Key Formula: Classification Head
P(y∣text)=softmax⁡(W h[CLS]+b),W∈RK×dP(y ∣ \text{text}) = \operatorname{softmax}(\mathbf{W}\, \mathbf{h}_{\text{[CLS]}} + \mathbf{b}), \qquad \mathbf{W} \in \mathbb{R}^{K \times d}P(y∣text)=softmax(Wh[CLS]​+b),W∈RK×d
(1)

A single linear layer on top of the sequence vector. With d=768d = 768d=768 and K=2K = 2K=2 classes, the head has only 768⋅2+2=1,538768 \cdot 2 + 2 = 1{,}538768⋅2+2=1,538 parameters; everything else is pretrained.

Token classification assigns a label to every token, for example for named entity recognition. The labels follow the BIO scheme: B-PER marks the first token of a person’s name, I-PER a following token of the same name, and O a token outside any entity, so that “Ada Lovelace visited Basel” is tagged B-PER I-PER O B-LOC. The head applies one linear layer to each token vector. Since a word may be split into several sub-word tokens, only the first sub-word of each word usually carries a label during training. Datasets such as CoNLL-2003 provide the annotations.

Span extraction finds the answer to a question inside a passage. The question and the passage form one input, separated by [SEP]. The head learns two vectors, s\mathbf{s}s for the start and e\mathbf{e}e for the end of the answer, and scores every token of the passage with them:

Key Formula: Span Extraction Head
Pstart(t)=softmax⁡t(s⊤ht),Pend(t)=softmax⁡t(e⊤ht)P_{\text{start}}(t) = \operatorname{softmax}_t(\mathbf{s}^\top \mathbf{h}_t), \qquad P_{\text{end}}(t) = \operatorname{softmax}_t(\mathbf{e}^\top \mathbf{h}_t)Pstart​(t)=softmaxt​(s⊤ht​),Pend​(t)=softmaxt​(e⊤ht​)
(2)

The answer is the span from the most likely start to the most likely end, with the end not before the start and the span not longer than a limit.

Example: Extracting an answer

A DistilBERT model fine-tuned on the SQuAD question-answering dataset receives the question “When was the University of Basel founded?” and the passage “The University of Basel was founded in 1460 and is the oldest university in Switzerland. Its faculty of science offers a master program in computer science.” The tokenizer turns both into 40 tokens; the year becomes the two sub-word tokens 146 and ##0. The start head gives 146 the probability 0.990, the next candidate “in” only 0.008; the end head gives ##0 the probability 0.999. The answer is “1460”. For the question “Which country is the university in?”, the same model extracts “switzerland” from the same passage.

Sentence embeddings need no new head, but a different loss. A bi-encoder pools the token vectors into one vector per text and is trained so that matching query-document pairs are close and other pairs are far apart, with the contrastive losses of Semantic Similarity with Transformers. A cross-encoder puts the query and the document into one input and uses a classification head with a single output, the relevance score; it is the reranker of the same section.

Frozen, Partial, or Full Fine-Tuning¶

How much of the pretrained model should change? Three strategies trade cost against accuracy.

A frozen encoder keeps all pretrained weights and trains the head alone. This is the linear probe of : it is fast, it needs few examples, and one encoder can serve many tasks at once, since the embeddings can be computed once and reused. Its accuracy is limited by how much of the task the pretrained representation already captures.

Full fine-tuning trains all weights together with the head. It reaches the best accuracy, because the representation itself adapts to the task, but it needs more labeled data and computation, and it produces a complete copy of the model for every task. With too much training, the model can also lose general abilities it had before, an effect called catastrophic forgetting. Text Classification compares a frozen and a fully fine-tuned encoder on the same sentiment task.

Partial fine-tuning trains only the top layers and freezes the lower ones, which hold the most general features. It sits between the two in cost and accuracy.

Hyperparameters and Pitfalls¶

Fine-tuning uses much smaller learning rates than training from scratch, because the pretrained weights are already good and large steps would destroy them. The authors of BERT recommended learning rates of 5⋅10−55 \cdot 10^{-5}5⋅10−5, 3⋅10−53 \cdot 10^{-5}3⋅10−5, or 2⋅10−52 \cdot 10^{-5}2⋅10−5, batch sizes of 16 or 32, and two to four epochs. The optimizer is usually AdamW (Training Deep Networks) with a weight decay around 0.01. The learning rate rises linearly during a short warm-up, typically the first 6 to 10% of the steps, and then decays linearly to zero.

A few pitfalls are common. Small datasets make fine-tuning unstable: two runs with different random seeds can differ by several percentage points, so results should be averaged over several seeds and compared on a validation set (Training and Model Selection). The model overfits within a few epochs, so the validation loss decides when to stop. Inputs longer than the maximum length are truncated, which may cut off the part that decides the label. And a text classifier trained on one kind of text, such as tweets, may transfer poorly to another, such as product reviews.

Parameter-Efficient Fine-Tuning¶

Full fine-tuning of a model with billions of parameters needs the memory for all weights, their gradients, and the optimizer state, and a full copy of the model for each task. Parameter-efficient fine-tuning freezes the pretrained weights and trains a small number of new parameters. Adapters insert small bottleneck layers into each transformer layer and train only those. LoRA (low-rank adaptation) adds to each frozen weight matrix W0∈Rd×d\mathbf{W}_0 \in \mathbb{R}^{d \times d}W0​∈Rd×d a trainable update of low rank rrr:

Key Formula: LoRA
W=W0+BA,B∈Rd×r,  A∈Rr×d,  r≪d\mathbf{W} = \mathbf{W}_0 + \mathbf{B}\mathbf{A}, \qquad \mathbf{B} \in \mathbb{R}^{d \times r}, \; \mathbf{A} \in \mathbb{R}^{r \times d}, \; r \ll dW=W0​+BA,B∈Rd×r,A∈Rr×d,r≪d
(3)

The pretrained matrix stays frozen; only the two thin matrices B\mathbf{B}B and A\mathbf{A}A are trained. After training, BA\mathbf{B}\mathbf{A}BA can be added to W0\mathbf{W}_0W0​, so the adapted model runs as fast as the original.

Example: How few parameters LoRA trains

A projection matrix of BERT-base has 768⋅768=589,824768 \cdot 768 = 589{,}824768⋅768=589,824 weights. LoRA with rank r=8r = 8r=8 trains 2⋅768⋅8=12,2882 \cdot 768 \cdot 8 = 12{,}2882⋅768⋅8=12,288 parameters instead, 2.1% of the matrix. Applied to the query and value projections of all 12 layers, LoRA trains 294,912294{,}912294,912 parameters, 0.27% of the 109,482,240109{,}482{,}240109,482,240 parameters of BERT-base. For GPT-3, the authors of LoRA report 10,000 times fewer trainable parameters and a third of the memory of full fine-tuning, with similar accuracy.

Since every task only needs its own small pair of matrices, one base model can serve many tasks, with the matching adapter loaded per request. QLoRA goes one step further: it stores the frozen base model in 4-bit numbers and trains LoRA adapters on top, which fits the fine-tuning of a 65-billion-parameter model onto a single graphics processor with 48 GB of memory.

A Fine-Tuning Loop¶

The following loop fine-tunes a small pretrained encoder for binary classification with the Hugging Face transformers library and plain PyTorch. AutoModelForSequenceClassification loads the pretrained encoder and adds a new, randomly initialized classification head; the model computes the cross-entropy loss itself when it receives the labels.

import torch
from transformers import AutoTokenizer, AutoModelForSequenceClassification

name = "sentence-transformers/all-MiniLM-L6-v2"          # 22.7M parameters
tokenizer = AutoTokenizer.from_pretrained(name)
model = AutoModelForSequenceClassification.from_pretrained(name, num_labels=2)

optimizer = torch.optim.AdamW(model.parameters(), lr=5e-5, weight_decay=0.01)
model.train()
for texts, labels in train_batches:                       # mini-batches of 32 examples
    enc = tokenizer(texts, padding=True, truncation=True,
                    max_length=64, return_tensors="pt")
    loss = model(**enc, labels=torch.tensor(labels)).loss  # cross-entropy
    loss.backward()                                       # backpropagation
    optimizer.step()
    optimizer.zero_grad()

Freezing the encoder and training only the head takes one more line before the loop, for p in model.base_model.parameters(): p.requires_grad = False. A learning-rate schedule with warm-up, an evaluation on validation data after each epoch, and several seeds complete a careful run. Higher-level tools, such as the Trainer of the same library or the training utilities of sentence-transformers for embedding models, wrap this loop.

Fine-Tuning or Retrieval?¶

Fine-tuning changes how a model behaves: the labels it assigns, the format and style of its outputs, the tasks it can perform. It is a poor way to give a model new facts. Facts learned into the weights cannot be updated without training again, cannot be cited, and mix with what the model already believed. Retrieval-augmented generation supplies facts at query time instead, as Evaluating RAG discusses: fine-tune for behavior, retrieve for knowledge.
