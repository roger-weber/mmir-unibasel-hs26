Multimodal Transformers

Show a photo of the Matterhorn to a current multimodal language model and ask for a description. The answer reads like the work of a careful human annotator: “The image centers on a single, dramatic mountain peak with a sharp, pyramid-like summit. Its steep faces are streaked with snow and dark gray rock. The peak looks like the Matterhorn in the Swiss Alps, a shape recognized around the world.” The model recognized a specific named entity, described the scene, the colors, and the lighting, and did so without any task-specific training.

Transformers process sequences of tokens. Transformer Embeddings applied them to text. The Vision Transformer applies them to images: it cuts an image into patches of 16 by 16 pixels and processes the patches like the tokens of a sentence. Multimodal transformers combine both: they encode images, audio, or video together with text. For retrieval, they offer two paths across the semantic gap. The first path generates text that describes the content and then searches the text. The second path maps content and text into one shared embedding space and compares them directly. This section covers both and compares them.

Describe, Then Search Text¶

An image-to-text model has two parts. A visual encoder, usually a Vision Transformer, turns the image into a sequence of embeddings. A transformer decoder generates text token by token. Through cross-attention, each generated token looks at the image embeddings, so the words follow the visual content. Such models are trained on large collections of image-caption pairs. Current multimodal language models go one step further: the image embeddings enter a full language model together with a text prompt, so the user controls through the prompt what the model writes.

This control turns the model into a configurable metadata extractor. Figure 1 shows a two-step pipeline for the Matterhorn photo. The first prompt asks for a detailed description of the main subject, the setting, the colors, and the lighting. The second prompt asks for a JSON document with predefined fields: a headline, keywords, named entities, dominant colors and shapes, extracted text, and boolean flags such as people_present and is_outdoors.

Each field of the JSON document has a place in the index of 4 - Index for Text Retrieval. The headline and the description become text fields for BM25 and for text embeddings. The keywords and named entities become fields for exact matching and facets. The boolean fields become filters: “outdoor photos without people” is a simple filter query. The prompt decides which metadata the archive gets, at which level, and in which format. Changing the schema means changing the prompt, not retraining a model. A good starting point for writing such prompts is to ask the model itself to draft a prompt from a short specification, a technique called meta-prompting.

The same path works for other media. A speech recognition model such as Whisper transcribes the spoken words of a podcast, an interview, or a video into text with timestamps. It is a transformer that encodes the audio signal and decodes text tokens, trained on 680,000 hours of weakly labeled audio from the web. Text recognition (OCR) extracts the words shown in images and videos, from street signs to presentation slides. For video, a multimodal model can describe the frames of each shot. In all cases, the output is text, and the complete text toolkit applies: BM25, embeddings, filters, and the retrieval-augmented generation of 7 - Retrieval Augmented Generation.

The describe path has clear strengths. The metadata is readable, so an archivist can check and correct it. The search uses mature, cheap, and well-understood text indexes. Search results can be explained, because each hit matched specific words. But it also has a fundamental limit: the index contains only what the model chose to write at indexing time. If the description of a beach photo does not mention the red umbrella in the corner, the query “red umbrella” will not find the photo. Generating rich descriptions for every item is also expensive, because a large model must process each item once, and again whenever the prompt changes.

The Eighth Obstacle: Hallucination¶

Doctorow’s seven obstacles in Metadata and Its Limits describe the weaknesses of human metadata, and Automated Feature Extraction showed that classifiers confuse similar classes. Generated metadata adds an eighth obstacle that is harder to spot: models hallucinate. A language model produces the most plausible continuation of its input, not a verified statement of fact. When the visual evidence is weak, it fills the gap with a plausible guess and states it with the same confidence as a correct observation. A mountain that resembles the Matterhorn may be labeled “Matterhorn”; a person in a suit at a lectern may be named after a well-known politician; text that is too small to read may be “extracted” anyway.

Hallucinations are especially harmful for specific metadata, such as names, places, and dates, because users trust exactly these fields. Several measures reduce the risk. The prompt can ask the model to mark uncertain values or to leave a field empty when the evidence is unclear. Generated values can be cross-checked against independent metadata: if the EXIF GPS coordinates place the photo in Canada, the label “Matterhorn” is wrong. Specific named entities can be restricted to a controlled list, such as the known persons of a news archive. For high-value collections, a human verifies the generated metadata, which is far cheaper than writing it from scratch.

Generated metadata looks better than it is

Generated descriptions are fluent, detailed, and consistent in style, so they look more reliable than the terse keywords of human annotators. It is tempting to judge the quality of generated metadata by reading a few examples. Evaluate it like any other classifier: sample items, compare the generated fields with ground truth, and measure precision and recall per field.

A Shared Embedding Space¶

The second path avoids the detour through text. It rests on one idea: all modalities can be mapped into the same embedding space, so that one comparison works across text, images, audio, and video. Two kinds of models build such a space, and they use it in different ways.

Multimodal language models map an image into the embedding space of their text tokens. The open model LLaVA, for example, encodes the image with a Vision Transformer and multiplies each output vector by a learned projection matrix. The result is a sequence of image tokens with the same dimension as the word embeddings of the language model, which then reads the image tokens and the text prompt as one sequence. This is what the describe path above relies on. The shared space stays inside the model, however: an image becomes a sequence of tokens, not one vector that an index can store and compare.

Dual encoders train one encoder per modality and align their outputs, so that an image and its caption get nearby vectors. Every item becomes one vector, which a vector index can store and search. The best-known dual encoder is CLIP (Contrastive Language-Image Pre-training), published by OpenAI in 2021. Its text encoder is a transformer, and its image encoder is a Vision Transformer or a convolutional network; both map their input to a vector of the same dimension. CLIP learned from 400 million image-caption pairs collected from the web: training pulls the vectors of matching pairs together and pushes mismatched pairs apart, and the captions that people wrote for their images are the only supervision. After training, the shared space supports retrieval in every direction. For text-to-image search, the system encodes every image of the collection once and stores the vectors in a vector index from 6 - Vector Search. A text query such as “a snow-covered mountain at sunrise” is encoded with the text encoder, and a nearest-neighbor search returns the closest images. No keyword was ever attached to them. For image-to-image search, the query is an image, and the same index returns visually and semantically similar images. For image-to-text search, the system finds the captions or documents closest to an image.

The shared space also turns CLIP into a classifier for any set of classes, without training. For zero-shot classification, the system writes a short text prompt for each class, such as “a photo of a mountain”, encodes the prompts, and assigns the image to the class whose prompt is closest. Text classifiers use the same idea with a short description of each class; Text Classification compares it with trained classifiers and with prompting a language model.

The same five prompts assign a photo of Roger Federer to “a photo of a tennis player” with 99.9998%: its similarity is 0.304, against 0.157 to 0.163 for the other prompts.

The absolute values are low: between an image and a text, cosine similarities typically lie between 0.1 and 0.4, and what carries the information is the difference between the candidates, which the temperature amplifies.

Dual encoders are not limited to images and text. CLAP (Contrastive Language-Audio Pre-training) applies the same idea to audio clips and their descriptions, so a query such as “dog barking in the rain” can retrieve sound recordings. Video models embed frames or short clips and align them with transcripts and captions. Newer models embed several modalities into one space.

Choosing a Path¶

The two paths answer different needs, and many systems use both.

AspectDescribe, then search textShared embedding space
IndexText index (inverted file), fields, filtersVector index of media embeddings
QueriesKeywords, names, filters, boolean conditionsFree-text descriptions, example images
CoverageOnly what the description mentionsAny visual concept the model learned
ExplainabilityHigh: matched words are visibleLow: a similarity score only
Specific entitiesGood, if the model names them correctlyWeak for rare names and exact identifiers
Indexing costHigh: a large generative model per itemModerate: one encoder pass per item
Typical failureHallucinated or missing detailsPlausible but wrong neighbors

The describe path excels at specific facts, filters, and explainable results: “photos of the Matterhorn taken in winter without people”. The embedding path excels at visual concepts that nobody thought to describe: “a lonely bench in the fog”. A hybrid system runs both and fuses the rankings with reciprocal rank fusion, which scores each item by summing 1/(k+rank)1/(k + \text{rank})1/(k+rank) over the result lists, as Building Semantic Search does for sparse and dense text retrieval. The generated descriptions can also serve as passages in a multimodal retrieval-augmented generation pipeline, where a language model answers questions about an image archive.
