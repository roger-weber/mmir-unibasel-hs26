Distance and Similarity Measures

Consider again the query “heart disease”. In Vector Space Retrieval, the query and every document became TF-IDF vectors. These vectors are sparse: the query vector has only two non-zero components, one for “heart” and one for “disease”. An inverted file therefore reads just two posting lists, and a document that contains neither term is never touched. The embeddings of Building Semantic Search represent the same query as a dense vector with typically 768 components, all of them non-zero. Components can be positive or negative, so a document may gain score in one dimension and lose it in another, and even a small query component qkq_kqk​ matters when the matching document component di,kd_{i,k}di,k​ is large. No document can be skipped because it lacks a query term. So far we have answered dense queries with a linear scan over all document vectors. Can we do better?

Text is not the only source of vectors. Later chapters on visual, audio, and video features describe images, sounds, and video shots by vectors of low-level perceptual features, such as the distribution of colors in an image. These features differ from embeddings in how they are obtained: a hand-designed extraction rule computes them directly from the signal. They also differ in how they are compared. Perceptual features usually come with a distance, such as Euclidean distance, where a smaller value means a better match. As with embeddings, the comparison function belongs to the feature. It follows from how the feature was defined or learned, and we cannot simply replace it with another one.

For both approaches, the search task is the same. A linear scan compares the query with every stored vector and returns the best matches. A better approach organizes the vectors in advance, as the inverted file does for sparse vectors, so that a query visits only a small part of the collection. This task is the nearest-neighbor problem. It is well understood in two and three dimensions, where geographic information systems and computer graphics have solved it for decades. With embeddings of hundreds or thousands of dimensions, it has gained new interest. This section formalizes what a best match is, first under a similarity score and then under a distance. The rest of the chapter asks how to find the best matches without a full scan.

Best-match search with similarity scores¶

Embeddings are compared with the dot product or with cosine similarity, the two measures of the vector space model in Vector Space Retrieval. Writing the query vector as q\mathbf{q}q and a document vector as di\mathbf{d}_idi​, the dot product sums the products of matching components, while cosine similarity divides that sum by the two vector lengths so that only direction matters.

(1)
simcos(q,di)=q⋅di∥q∥ ∥di∥\text{sim}_{\text{cos}}(\mathbf{q}, \mathbf{d}_i) = \frac{\mathbf{q} \cdot \mathbf{d}_i}{\lVert \mathbf{q} \rVert \, \lVert \mathbf{d}_i \rVert}simcos​(q,di​)=∥q∥∥di​∥q⋅di​​
(2)

The dot product rewards vectors that are both aligned and long; cosine similarity divides out the lengths and rewards alignment alone.

Figure 1 contrasts the geometry of the two measures. For cosine similarity (left), the best matches lie inside a cone around the query, and the length of a document vector plays no role. For the dot product (right), a hyperplane orthogonal to the query separates the best matches from the rest. Documents farther out along the query direction score higher, so the dot product favors long vectors. A document in the half-space opposite the query scores negatively under both measures.

With a comparison function in place, we can state the search problem. Given a query embedding q\mathbf{q}q and a set P\mathbb{P}P of stored document embeddings, we look for the documents that maximize the score.

Key Formula: Best-Match Search
d∗=arg⁡max⁡di∈Psim(q,di),sim∈{simdot,simcos}\mathbf{d}^{*} = \arg\max_{\mathbf{d}_i \in \mathbb{P}} \text{sim}(\mathbf{q}, \mathbf{d}_i), \qquad \text{sim} \in \{\text{sim}_{\text{dot}}, \text{sim}_{\text{cos}}\}d∗=argdi​∈Pmax​sim(q,di​),sim∈{simdot​,simcos​}
(3)

More generally, the top-kkk result consists of the kkk documents with the highest scores. The definition says nothing about how to find them; a linear scan computes all scores and keeps the best.

In practice, the choice between the two measures is often made once, when the index is built. Most embedding models output vectors of unit length, and otherwise we normalize every document vector once before indexing, d^i=di/∥di∥\hat{\mathbf{d}}_i = \mathbf{d}_i / \lVert \mathbf{d}_i \rVertd^i​=di​/∥di​∥. On the unit sphere, cosine similarity and dot product coincide, so the index only needs to compute dot products. The query needs no normalization at all:

simcos(q,di)=1∥q∥  q⋅d^i\text{sim}_{\text{cos}}(\mathbf{q}, \mathbf{d}_i) = \frac{1}{\lVert \mathbf{q} \rVert}\; \mathbf{q} \cdot \hat{\mathbf{d}}_isimcos​(q,di​)=∥q∥1​q⋅d^i​
(4)

The factor 1/∥q∥1/\lVert \mathbf{q} \rVert1/∥q∥ is the same for every document. It scales all scores of a query equally and leaves the ranking unchanged. Normalizing the query does no harm, and it is useful when scores must be comparable across queries, for example against a fixed similarity threshold. For ranking alone, it is not required.

Nearest-neighbor search with distances¶

To see how a perceptual feature turns media into a vector, consider the color content of an image. Figure 2 splits a photograph into its red, green, and blue channels and summarizes each channel by a histogram over its 256 intensity values. To build the histograms, we visit every pixel and increase three bins by one: the bin for the pixel’s red intensity in the red histogram, and likewise for green and blue. The three histograms together hold 3×256=7683 \times 256 = 7683×256=768 counts, which we read as a 768-dimensional feature vector of the image.

Exact intensities are too fine-grained for comparing images. Two photographs of the same pasta under slightly different light would share hardly any bins. We therefore quantize each histogram into fewer, wider bins, for example 16 bins per channel that each cover 16 intensity values. Similar shades now fall into the same bin, and the feature vector shrinks to 3×16=483 \times 16 = 483×16=48 values, each counting the pixels in one bin.

To compare two images by their colors, we sum the absolute differences of their counts over all 48 bins. Two images with similar color distributions differ little in every bin and receive a small sum. A photograph of a blue sky differs strongly from the red pasta in many bins and receives a large sum. This sum is the Manhattan distance between the two feature vectors. The color histogram is deliberately simple: it only shows how image content is reduced to a vector. Later chapters introduce more expressive perceptual features.

A distance δ(q,pi)\delta(\mathbf{q}, \mathbf{p}_i)δ(q,pi​) between the query q\mathbf{q}q and a stored vector pi\mathbf{p}_ipi​ reverses the direction of comparison: a smaller value means a better match, and identical vectors have distance zero. Most distances used in retrieval are metrics, which means they are non-negative, symmetric, and satisfy the triangle inequality. Each distance induces a different notion of a neighborhood, that is, a different shape for the set of points within a fixed distance of a center. Figure 3 shows these shapes in 2D.

  • Euclidean distance (L2) measures straight-line distance and gives a round neighborhood. It is the default for continuous features.

  • Manhattan distance (L1) sums the absolute differences per dimension and gives a diamond neighborhood. It emphasizes many small differences.

  • Maximum distance (L-infinity) takes the single largest component difference and gives a square neighborhood. It lets the worst dimension dominate.

  • Quadratic distance weights and correlates the dimensions through a matrix, giving a tilted-ellipse neighborhood.

Distances and similarity scores are two views of the same comparison. On the unit sphere the link is exact. For normalized vectors, the squared Euclidean distance is a linear function of the dot product:

∥q^−d^i∥2=2−2 q^⋅d^i\lVert \hat{\mathbf{q}} - \hat{\mathbf{d}}_i \rVert^2 = 2 - 2\, \hat{\mathbf{q}} \cdot \hat{\mathbf{d}}_i∥q^​−d^i​∥2=2−2q^​⋅d^i​
(5)

Ranking normalized vectors by increasing Euclidean distance therefore returns the same order as ranking them by decreasing cosine similarity. In general, any distance can be turned into a similarity score with a decreasing function, such as 1/(1+δ)1/(1 + \delta)1/(1+δ), without changing the ranking. Such a conversion keeps the comparison and changes only the scale of the values. Replacing the comparison is a different matter. Using cosine similarity instead of the Manhattan distance on color histograms changes the ranking, and only the design of the feature can justify that change.

One awkward property of distances is that they are hard to read on their own. A cosine of 0.9 clearly signals a strong match, but a distance of 32.8 says nothing until it is compared with other distances. This is one reason why normalized similarity scores are convenient when a human or a downstream system needs to interpret the score.

With a distance, the search problem keeps its form. We minimize instead of maximize, and the best match becomes the nearest neighbor.

Key Formula: Nearest-Neighbor Search
NN(q)=arg⁡min⁡pi∈Pδ(q,pi)\text{NN}(\mathbf{q}) = \arg\min_{\mathbf{p}_i \in \mathbb{P}} \delta(\mathbf{q}, \mathbf{p}_i)NN(q)=argpi​∈Pmin​δ(q,pi​)
(6)

The kkk nearest neighbors are the kkk stored vectors with the smallest distances. This is best-match search with the direction of comparison reversed; for normalized vectors under Euclidean distance, both return the same result.

Keeping dimensions comparable¶

Embeddings rarely need further adjustment, because every dimension comes from the same learned space and lives on a comparable scale. Perceptual features are different. A feature vector often combines values that were measured independently, and the color histogram shows two forms of the resulting problem.

The first is scale. Bin counts depend on the size of the image: a photograph with four times as many pixels has four times larger counts, so the Manhattan distance between a small and a large image of the same scene is large. This is the same problem the dot product has with long documents in Vector Space Retrieval, and the fix is similar. We divide every count by the number of pixels. Each channel’s histogram then holds fractions that sum to 1, independent of the image size.

The second is mixing features. Suppose we append the image’s average brightness, measured on a scale from 0 to 255, to the 48 normalized bins. The bins of each channel sum to 1, so the Manhattan distance over all 48 bins can never exceed 6. A brightness difference of 50 alone outweighs any possible color difference, and the distance effectively compares brightness only. To give each dimension a fair share, we rescale it by its spread over the collection. For each dimension jjj, we subtract the mean μj\mu_jμj​ and divide by the standard deviation σj\sigma_jσj​ of that dimension, both estimated once from the collection or from a representative sample.

v^j=vj−μjσj\hat{v}_j = \frac{v_j - \mu_j}{\sigma_j}v^j​=σj​vj​−μj​​
(7)

After this Gaussian normalization, every dimension has mean 0 and unit variance. A difference of one unit then means the same in every dimension: one standard deviation of the typical variation. Equivalently, the distance weights each dimension’s difference by 1/σj1/\sigma_j1/σj​, so each dimension contributes in proportion to how much it actually varies.

Normalize on statistics, not on a single query

Gaussian normalization uses the mean and standard deviation of the whole collection, not of one query or one result set. Estimate μj\mu_jμj​ and σj\sigma_jσj​ once from a representative sample and keep them fixed, so that the same vector always maps to the same normalized point regardless of which query retrieves it.

Gaussian normalization treats the dimensions as independent, but the bins of a color histogram are not. The bin for red is related to the bin for orange, because the two colors are perceptually close, while red and blue are not. The quadratic distance captures such relationships through a positive semi-definite matrix A\mathbf{A}A, whose eigenvectors define the main axes of the data and whose eigenvalues scale them.

Computing (q−pi)⊤A(q−pi)(\mathbf{q} - \mathbf{p}_i)^\top \mathbf{A} (\mathbf{q} - \mathbf{p}_i)(q−pi​)⊤A(q−pi​) for every candidate is expensive, but an eigenvalue decomposition avoids it. Rotating and scaling the space along the eigenvectors of A\mathbf{A}A, shown in Figure 4, maps the quadratic distance in the original space onto a plain Euclidean distance in the transformed space. We transform all vectors once when building the index and then compare them with ordinary Euclidean distance at query time.

Whether we maximize a similarity score or minimize a distance, we now have a precise definition of the best matches. The rest of the chapter answers a single question about these definitions: how do we compute the arg-max or arg-min without comparing the query to every stored vector? For a few thousand vectors a full scan is fine. For millions or billions it is not, and the structures that speed up the search behave very differently depending on how many dimensions the vectors have.
