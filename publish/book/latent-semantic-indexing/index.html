Latent Semantic Indexing

In classical retrieval, documents are sparse high-dimensional vectors with TF-IDF weights, and similarity depends on shared terms. This term independence assumption limits recall: a document about “automobile maintenance” will not match a query for “car repair” unless we explicitly expand the query with synonyms. Stemming and lemmatization reduce some mismatches, but they are language-specific, require manual effort, and cannot capture domain-specific relationships. A search for “tokens” in a text processing context should also retrieve paragraphs discussing “terms” or “words”, but no stemmer will make that connection.

Latent Semantic Indexing (LSI) addresses this by projecting the high-dimensional term-document space into a compact, lower-dimensional representation where semantically related terms are brought closer together. The key insight is that terms appearing in similar document contexts are likely related, even if they never co-occur in the same document. By reducing dimensionality, LSI forces the model to merge these co-occurrence patterns into latent topics.

LSI in historical context (optional reading)

LSI was developed at Bellcore (Bell Communications Research) in the late 1980s by a team that included Scott Deerwester and Susan Dumais. The first papers appeared in 1988, and a foundational patent was filed the same year and granted in 1989 (since expired). LSI demonstrated that unsupervised dimensionality reduction could improve retrieval quality, a foundational idea that influenced all subsequent embedding methods. Despite this conceptual contribution, LSI faced two practical barriers: the expensive SVD computation over large matrices, and the inability to use inverted indices for the resulting dense vectors. While computational costs have since become manageable, LSI has been superseded by neural embedding methods that capture finer-grained semantic associations and transfer across collections.

Singular Value Decomposition¶

Recall from the vector space model that we represent a collection as a term-document matrix A\mathbf{A}A of size m×nm \times nm×n, where mmm is the vocabulary size and nnn the number of documents. Each entry aija_{ij}aij​ holds the TF-IDF weight of term iii in document jjj. Most entries are zero because any single document uses only a small fraction of the vocabulary, making A\mathbf{A}A extremely sparse.

LSI builds on the Singular Value Decomposition (SVD), which factorizes this matrix into three components. Given A\mathbf{A}A of rank rrr, the SVD produces:

A=USV⊤\mathbf{A} = \mathbf{U} \mathbf{S} \mathbf{V}^\topA=USV⊤
(1)

where U\mathbf{U}U is an m×rm \times rm×r orthonormal matrix (each row is one term’s representation in the rrr-dimensional latent space), S\mathbf{S}S is an r×rr \times rr×r diagonal matrix of singular values in decreasing order, and V\mathbf{V}V is an n×rn \times rn×r orthonormal matrix (each row is one document’s representation in the latent space). Note that Figure 1 shows V⊤\mathbf{V}^\topV⊤ rather than V\mathbf{V}V, so the document representations appear as columns of V⊤\mathbf{V}^\topV⊤ (equivalently, rows of V\mathbf{V}V).

The singular values on the diagonal of S\mathbf{S}S decrease rapidly in magnitude. By retaining only the kkk largest singular values and their corresponding columns in U\mathbf{U}U and V\mathbf{V}V, we obtain the best rank-kkk approximation of A\mathbf{A}A under the Frobenius norm:

Ak=UkSkVk⊤\mathbf{A}_k = \mathbf{U}_k \mathbf{S}_k \mathbf{V}_k^\topAk​=Uk​Sk​Vk⊤​
(2)

The parameter kkk is a hyperparameter that controls a quality-storage tradeoff. The original matrix A\mathbf{A}A has m×nm \times nm×n entries. The truncated representation stores Uk\mathbf{U}_kUk​ (m×km \times km×k) and Vk\mathbf{V}_kVk​ (n×kn \times kn×k), plus the kkk singular values, totaling (m+n+1)×k(m + n + 1) \times k(m+n+1)×k values. For typical collections where k≪min⁡(m,n)k \ll \min(m, n)k≪min(m,n), this is a large reduction. Choosing kkk too small loses semantic detail; choosing kkk too large retains noise and increases storage demand, and in our application, retrieval cost. In practice, values between 100 and 300 work well for text collections.

Figure 2 illustrates the truncated decomposition. Compared to Figure 1, the matrices are now much smaller: Uk\mathbf{U}_kUk​ has only kkk columns (one per latent topic) and Vk⊤\mathbf{V}_k^\topVk⊤​ has only kkk rows.

The kkk dimensions no longer correspond to individual terms. Each dimension represents a latent topic, a pattern of term co-occurrence across documents. We can interpret a topic by examining the terms with the largest weights in the corresponding column of Uk\mathbf{U}_kUk​.

Folding In New Documents and Queries¶

When a new document d\mathbf{d}d arrives (represented as a term vector in the original mmm-dimensional space), we project it into the kkk-dimensional latent space without recomputing the full SVD (see Figure 3):

dˉ⊤=d⊤UkSk−1\bar{\mathbf{d}}^\top = \mathbf{d}^\top \mathbf{U}_k \mathbf{S}_k^{-1}dˉ⊤=d⊤Uk​Sk−1​
(3)

A new document (or query) vector d\mathbf{d}d is mapped to the latent topic space by multiplying with UkSk−1\mathbf{U}_k \mathbf{S}_k^{-1}Uk​Sk−1​. This is valid as long as the new document does not significantly alter the collection’s topic structure.

Queries are treated as short documents. The query vector q\mathbf{q}q (with non-zero entries for query terms) is projected identically:

qˉ⊤=q⊤UkSk−1\bar{\mathbf{q}}^\top = \mathbf{q}^\top \mathbf{U}_k \mathbf{S}_k^{-1}qˉ​⊤=q⊤Uk​Sk−1​
(4)

Retrieval then computes cosine similarity between the projected query and all projected documents:

Worked Example¶

Consider a collection of 9 documents split into two groups: five about human-computer interfaces (c1-c5) and four about graph algorithms (m1-m4):

IDTitle
c1Human machine interface for Lab ABC computer applications
c2A survey of user opinion of computer system response time
c3The EPS user interface management system
c4System and human system engineering testing of EPS
c5Relation of user-perceived response time to error measurement
m1The generation of random, binary, unordered trees
m2The intersection graph of paths in trees
m3Graph minors IV: Widths of trees and well-quasi-ordering
m4Graph minors: A survey

A search for “human computer interaction” should retrieve c1-c5, but not every document contains those exact terms. Traditional retrieval requires explicit query expansion.

After constructing the term-document matrix (using term frequencies, excluding stop words and terms appearing only once), we compute the SVD and truncate to k=2k=2k=2 topics (Figure 4).

Only “human” and “computer” appear in the vocabulary, so the query is the sparse 12-dimensional vector with two active entries. Folding it into the 2D topic space with the projection formula yields qˉ=(0.138, −0.028)\bar{\mathbf{q}} = (0.138,\ {-0.028})qˉ​=(0.138, −0.028), as shown in Figure 5.

Placing this query alongside the documents in the latent plane (see Figure 6) shows it pointing toward the c-documents:

Using cosine similarity, documents rank as: c3 (0.997) > c1 (0.997) > c4 (0.979) > c2 (0.895) > c5 (0.846), with all c-documents retrieved before any m-document (every m-document scores below zero). Notably, c3 (“The EPS user interface management system”) ranks highest despite containing neither “human” nor “computer”. The SVD has recognized that its terms (“EPS”, “user”, “interface”, “system”) co-occur with query-related terms in other documents, connecting them through the latent topic structure.

The two topics can be interpreted from the largest-weight terms in each column of Uk\mathbf{U}_kUk​:

  • Topic 1: 0.64·system + 0.40·user + 0.30·EPS + 0.27·time + 0.27·response + 0.24·computer

  • Topic 2: 0.62·graph + 0.49·trees + 0.45·minors + 0.27·survey

Sign ambiguity in SVD

The signs of the singular vectors are not unique. Flipping the sign of a column of Uk\mathbf{U}_kUk​ together with the matching row of Vk⊤\mathbf{V}_k^\topVk⊤​ gives an equally valid decomposition. Only the relative orientation of the latent coordinates carries meaning, so the absolute sign of a topic axis, and of individual coordinates such as the -0.028 above, depends on the SVD implementation. Cosine similarities are unaffected because query and documents are projected with the same Uk\mathbf{U}_kUk​.

Limitations of LSI¶

LSI demonstrated that latent semantic structure improves retrieval, but several limitations prevented widespread adoption:

  1. No inverted index acceleration: projected document vectors are dense, so every query requires comparison against all documents. The pruning strategies that make inverted indices fast (early termination, skip pointers) do not apply.

  2. Corpus-specific topics: the learned mapping depends on both terms and documents in the collection. An LSI model trained on IT articles performs poorly on biomedical text. Unlike modern embeddings, LSI representations do not transfer across domains.

  3. Static vocabulary: new terms can only be approximated through the existing topic structure. Two new terms in the same document receive identical representations, since both depend solely on that document’s projection into Vk\mathbf{V}_kVk​.

  4. No sub-word awareness: LSI operates at the word level and cannot generalize to morphological variants or misspellings not already in the vocabulary.

  5. Linear assumption: SVD captures linear relationships between terms and documents. Non-linear semantic patterns (metaphor, irony, context-dependent meaning) are beyond its reach.

Despite these limitations, LSI established the foundational principle that underpins all modern semantic search: by reducing dimensionality, we can discover latent structure that connects terms sharing similar usage patterns, even when they never co-occur directly. The methods that follow in this chapter, from Word2Vec to transformers, all build on this insight while addressing LSI’s specific shortcomings.
