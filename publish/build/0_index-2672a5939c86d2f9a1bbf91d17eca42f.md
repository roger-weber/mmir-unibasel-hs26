# 2 - Performance Evaluation

A student searches a university library for books that provide the computer science foundations needed for a master's degree. One search system returns many useful books mixed with unrelated titles. Another returns fewer useful books, but places them near the top. Which system is better? The answer depends on what the student needs: broad coverage, a clean result set, or the best books in the first few positions.

Performance evaluation turns claims such as "better results" into measurements that can be checked and reproduced. A fair comparison requires more than a metric. It needs a representative collection, realistic information needs, consistent relevance judgments, and a clear definition of success. Without this shared benchmark, a higher score may reflect an easier test rather than a better retrieval method.

The same principles apply when a text system chooses a label or action instead of retrieving documents. A spam filter must detect unwanted messages without hiding legitimate email. An intent router must decide whether a query should use an internal knowledge base, search the web, invoke a calculator, or ask for clarification. Confusion matrices expose the errors these systems make, while per-class measures and score thresholds reveal trade-offs that accuracy alone can hide. No prior knowledge of classifier training is required to evaluate their output.

```{admonition} What you'll learn
:class: tip
- Design a retrieval benchmark from a document collection, information needs, relevance judgments, and performance goals
- Explain when evaluation should treat results as an unordered set, a ranking, or a ranking with graded relevance
- Calculate and interpret precision, recall, fallout, F-measures, and macro and micro averages
- Evaluate rankings using reciprocal rank, average precision, mean average precision, and normalized discounted cumulative gain
- Interpret confusion matrices, class imbalance, decision thresholds, ROC curves, and AUC for text classification
```
